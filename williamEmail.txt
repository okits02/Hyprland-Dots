1: @dwilliam62 requested changes on this pull request.

Problem
PR #159 adds a second, independent monitor-management system to the repo. It stores device-identity layouts in UserConfigs/display-layouts.json and applies them at runtime through hyprctl eval, alongside the repo's existing Lua monitor system (UserConfigs/monitors.lua, Monitor_Profiles/*.lua, MonitorProfiles.sh, user_laptops.lua).

The internal engineering is strong, but the integration layer is not. On a fresh clone it works; on an installed system it does nothing, it duplicates an existing system it deliberately refuses to cooperate with, it applies state only at runtime so a reload undoes it, and its nwg-displays bridge targets a file format that tool no longer writes for Lua configs. It also carries unrelated edits and no changelog entry.
Current state
The pieces that matter for integration, all verified on pr159:
scripts/lib_copy.sh:563 only adds UserConfigs files that are missing. So the PR's three activation edits (user_startup.lua starts MonitorWatcher.sh; user_keybinds.lua adds SUPER+ALT+D/W; user_laptops.lua gains do return end at line 28) never reach an existing install. The repo's actual mechanism for this is patches/NN-*.sh, run by scripts/lib_patches.sh on install/upgrade/express and the menu update, documented in docs/Patching-UserConfigs.md; patches/50, 60 and 70 already maintain user_laptops.lua.
lua/monitors.lua:38-46 loads UserConfigs/monitors.lua at config load, and user_laptops.lua resolves modes, positions and scales from that same file. A declarative layout written there is therefore reload-proof and makes user_laptops.lua compatible instead of conflicting.
nwg-displays writes only monitors.conf in 0.3.28 (the version installed here) and then calls hyprctl reload plus dispatch dpms, so the claim in the code comments and docs that it "never applies anything at runtime" is false, and that reload is what makes the arrangement snap back before the import runs. From 0.4.3 it also writes the Lua sibling, derived as outputs_path.removesuffix(".conf") + ".lua" when the path ends in .conf, else the hardcoded ~/.config/hypr/monitors.lua.
DisplayProfile.sh:379-395 (dp_stand_down) makes the new system stand down whenever UserConfigs/monitors.lua contains real hl.monitor calls - which is exactly what MonitorProfiles.sh writes, and what a generated layout would write.
bash config/hypr/scripts/tests/run-all.sh passes 439 checks; shellcheck is clean apart from two false positives caused by the dynamic source path.
Proposed changes

Make the layout declarative
Have DisplayProfile.sh write the resolved layout to UserConfigs/monitors.lua as hl.monitor({...}) entries (plus a -- Generated by DisplayProfile.sh marker and the fingerprint), then reload, instead of applying only through hyprctl eval. This is the single change that makes everything else fall into place: lua/monitors.lua loads the file at startup, the layout survives a reload and a restart, user_laptops.lua honours it through its existing load_monitor_configs() path, and the configreloaded re-apply in MonitorWatcher.sh becomes a safety net rather than a load-bearing hack. Keep the runtime hyprctl eval apply as the immediate-effect step; the file write is what makes it durable.
Because the file becomes system-owned, invert dp_stand_down: stand down only when UserConfigs/monitors.lua has hl.monitor calls but no generated marker (a hand-edited or MonitorProfiles.sh-written file), and take ownership once a layout is saved for the current set.
2. Rework the nwg-displays bridge
Point -m at UserConfigs/monitors.conf rather than a state-dir discard. On nwg-displays 0.4.3+ the sibling UserConfigs/monitors.lua is then written to the file the Lua workflow already reads, and hyprctl reload applies the drag natively - no import, no snap-back, no hyprlang parsing.
Keep dp_import_nwg as the fallback for older nwg-displays (0.3.x writes only monitors.conf), and fix its defects: rename the discard path to end in .conf so the Lua sibling is contained; read the ,mirror, and ,bitdepth, extras instead of dropping them; tolerate a comma inside a desc: description rather than misaligning the fields.
Correct the false claims in the comments and the README about nwg-displays not applying anything, and document the Apply-time snap-back for the 0.3.x path.
3. Stop disabling user_laptops.lua
With change 1 in place there is no conflict to resolve: user_laptops.lua reads the same file the layout system writes. Drop the do return end, which also stops invalidating patches/50, 60 and 70. Keep its lid/clamshell handling as the single implementation and delete the duplicate lid binds added to user_startup.lua:113-129.
4. Activate through patches
Add patches/80-display-layouts.sh implementing the documented patch contract (content-idempotent, add-only, skip cleanly when the target is absent, exit 0 for applied and already-present), using patches/lib.sh helpers, to bring user_startup.lua and user_keybinds.lua up to date on existing installs. Update the shipped templates as well so fresh installs match. Add a check to the patch test set that runs the new patch twice against a temp KOOLDOTS_CONFIG_HOME and asserts the second run changes nothing.
5. Collapse the two profile systems into one
Decide and document one answer. Recommended: keep the new system as the front end and make MonitorProfiles.sh a thin shim that lists layouts from display-layouts.json, so SUPER+SHIFT+E and SUPER+ALT+D reach the same store, and Monitor_Profiles/*.lua becomes a legacy import. Failing that, at minimum remove the second keybind and state in the docs which system is authoritative.

3: Latest updates
I reviewed this in full and reworked the integration so the feature sits inside
the Lua workflow rather than beside it. The reworked version is on branch
pr159 (3 commits on top of the branch head, c8265730), and it is applied and
running on a live Debian forky install.

The layout is now declarative
DisplayProfile.sh applies a layout and writes it to
UserConfigs/monitors.lua, with a marker line and the monitor-set fingerprint.
lua/monitors.lua already loads that path on every config load, and
UserConfigs/user_laptops.lua already reads its rules from there — so one file
now drives the session, a reload and the laptop logic instead of three things
competing for the monitors.

That is why user_laptops.lua no longer has to be switched off: the do return end is gone, it stays the single owner of the lid switch, and the duplicate lid
binds added to user_startup.lua are removed.

nwg-displays works when you run it yourself
This was the biggest functional gap. The bridge only ran when the menu launched
nwg-displays, so a run from a terminal or a launcher lost the arrangement. The
watcher now watches nwg's own ~/.config/hypr/monitors.conf and imports it when
it changes, so any run works:

the signal is the file changing, not the process, so nothing has to know how
nwg was started;
while nwg is open the watcher drops monitor and reload events, so nwg's own
reload cannot undo the drag before the import lands;
the import does not wait for the window to close — the arrangement lands as
soon as Apply is pressed, and nwg's Cancel/revert writes the file back,
which imports the reverted arrangement in turn.
So no newer nwg-displays is needed anywhere. The bridge reads the hyprlang
.conf that every version writes — 0.3.20 (trixie), 0.3.28 (forky/sid) and
0.4.4 alike — so no distro has to build or backport anything. 0.4.3+ also
writes a Lua sibling at ~/.config/hypr/monitors.lua; this config deliberately
never loads that path, so the two do not compete.

Do not add require("monitors") to your config. nwg-displays' own README
suggests it for Hyprland 0.55+. It would make that sibling live, and it would
then fight UserConfigs/monitors.lua.

A bug the review turned up
MonitorWatcher.sh could strand its own lock. The event stream runs in a
process-substitution subshell that outlives the watcher, and 9>&- on the call
inside <(...) was not enough — bash saves and restores the descriptor around a
redirected command, and the saved copy kept the flock. Killing the watcher (a
restart, a logout, Ctrl-C) then left the lock held for as long as socat stayed
connected, and no watcher could start again. The subshell now closes fd 9 with
exec 9>&- before it starts the stream, and the watcher suite covers both the
self-exit and the killed case.

Activation on an existing install
All three things the feature needs in UserConfigs are edits to files copy.sh
only ever adds, so they never reached an install that already has them. This is
why the feature did nothing on an upgrade. patches/80-display-layouts.sh now
applies them, content-idempotently.

Also in this pass
MonitorProfiles.sh is a front end for the layout store, not a second system:
it lists this set's layouts and offers Monitor_Profiles/*.lua as a one-way
import.
lib_display_store.sh no longer generates a preferred mode (the validator
refuses it, so it produced a layout that could never be saved). The nwg parser
locates the mode/position/scale triple by shape, so a description containing a
comma no longer misaligns and drops the monitor, and mirror/bitdepth extras are
refused by name rather than silently discarded.
Review fixes: the pause file is written before nwg launches, import-nwg
records the running layout so a reload cannot revert an import, the setup table
reports the validator's real reason, and Refresh.sh's fallback takes its
directory as an argument instead of relying on bash's dynamic scoping.
Reverted two unrelated edits: hyprlock.conf (a line uncommented inside a
commented-out label {} block) and the .gitignore additions.
CHANGELOG.md entries under v2.3.28, and the docs rewritten for the Lua
model.
Testing
bash config/hypr/scripts/tests/run-all.sh — 495 checks, 0 failed (was
439). New coverage: the generated monitors.lua (validated with luac and
executed against a stubbed hl), reapply, the nwg parser's field shapes, the
direct-run path, and patch idempotency.
shellcheck -x -S warning clean across the feature scripts.
On the live install, with the runtime state wiped: a plain config reload

survives a reboot with no runtime state.
The two suites that need repo-side files (patches/, scripts/lib_copy.sh)
now skip cleanly when run from an installed config instead of failing.
